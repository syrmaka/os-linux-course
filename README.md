# os-linux-course — Правила ведения репозитория

## Основные правила организации работ

- **Одна работа — отдельная папка.** Каждый лабораторный или курсовой проект хранится в собственной директории (например, `lab_01`, `project_os_design`). Это упрощает навигацию и изолирует изменения между заданиями.  
- **Понятные имена файлов.** Используйте описательные названия без пробелов и спецсимволов: `system_diagnostics.md`, `cpu_monitoring.py`, `network_config.sh`. Избегайте имён вроде `file1`, `temp`, `draft`.  
- **Осмысленные коммиты.** В сообщении коммита кратко указывайте суть изменений:  
  - ✅ Хорошо: `add: script for RAM monitoring`, `fix: typo in README`, `update: CPU load table with new data`.  
  - ❌ Плохо: `commit`, `changes`, `fixed something`.  
- **Отсутствие секретов и персональных данных.** Не загружайте в репозиторий пароли, токены, ключи, логины, приватные SSH‑ключи, скриншоты с личными данными. Если в коде нужны настройки — используйте шаблон (например, `.env.example`) без реальных значений.
